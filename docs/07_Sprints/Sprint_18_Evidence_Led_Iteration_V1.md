# Sprint 18 Evidence-Led Iteration V1

Status: Reserved — scope intentionally unset until Sprint 17 decision
Prepared: 2026-08-19

## Intake Decision

### 1. Mainline fit

Evidence-led iteration protects ZEROON from feature accumulation. The Sprint
exists to solve one measured acquisition, activation, return, reflection, or
trust problem while preserving long-term companionship and private memory.

### 2. Drift risk

Preselecting a feature before Sprint 17 would turn assumptions into roadmap
facts. Combining positioning, Persona, onboarding, notification, pricing, and
core-loop changes would make the next result uninterpretable.

### 3. Recommended abstract capability

**One-problem evidence response**: select the smallest Backlog capability that
addresses the strongest measured problem, define one primary outcome, and keep
other variables stable.

### 4. Roadmap decision

Reserve Sprint 18 without approving a feature. Its scope may be written only
after Sprint 17 records separate acquisition, activation, return, and trust
decisions.

### 5. Planning acceptance criteria

- one evidence-backed problem is selected;
- the chosen Backlog item has an explicit causal hypothesis;
- baseline, denominator, maturity, and qualitative evidence are recorded;
- one primary product variable changes;
- privacy, ownership, consent, deletion, export, and failure boundaries are
  defined before implementation;
- continue, reshape, and stop criteria are accepted.

## Sprint Goal

Improve one measured problem without changing the ZEROON core promise or
making the next cohort impossible to interpret.

## Selection Matrix

| Sprint 17 evidence | Candidate response |
|---|---|
| Low product-page conversion | Store promise, screenshots, audience, or channel correction |
| Downloads but weak activation | First-loop explanation, reliability, or interaction hierarchy |
| Activation but weak return | Archive retrieval, review markers, or one bounded resurfacing experiment |
| Return without reflective value | Source-linked, user-requested reflection |
| Trust confusion | Memory correction, export, app protection, or clearer controls |
| Credible return but weak payment | Later package/price experiment without paid intimacy |
| No credible problem signal | Do not invent work; improve acquisition or continue observation |

## Planned Work

Only the selection workflow is approved now:

| ID | Task | Surfaces | Done when |
|---|---|---|---|
| `S18-01` | Read Sprint 17 decision evidence | product, research, evidence, support | Facts, interpretations, uncertainty, and blocked conclusions are separated |
| `S18-02` | Select one problem and Backlog capability | product, guardrail, roadmap | Mainline fit, drift risk, abstraction, priority, and rejected alternatives are recorded |
| `S18-03` | Write bounded implementation intake | affected surfaces only | API, database, mobile, admin, AI, privacy, tests, and release gates are explicit |
| `S18-04` | Obtain owner scope approval | roadmap, current state | Exact item, non-goals, authority, and acceptance evidence are accepted before implementation |
| `S18-05` | Implement and validate selected scope | determined later | Relevant quality, runtime, experience, and product evidence pass |
| `S18-06` | Record Continue, Reshape, or Stop | decision log, backlog, current state | Outcome updates the Backlog without rewriting unsupported claims |

## Acceptance Criteria

- Sprint 18 has no feature implementation before `S18-04`;
- selected work maps to a real `ZPB-*` item or creates a newly reviewed item;
- no unrelated feature joins because implementation is convenient;
- evidence events remain content-free and consent-controlled;
- the same measured cohort is not exposed to multiple uncontrolled changes;
- completion reports what improved, what did not, and what remains uncertain.

## Non-Goals

- automatic selection of a P1 or P2 feature;
- broad redesign;
- simultaneous Persona, onboarding, notification, payment, and core-loop work;
- feature count as success;
- physical ZEROON implementation unless Sprint 19 independently passes its
  entry gates.

## Stop Rules

Do not start implementation if Sprint 17 evidence is too small, immature, or
confounded to select a problem. Return to acquisition, observation, or a
bounded reliability fix instead of manufacturing certainty.
